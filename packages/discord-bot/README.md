# discord-bot

`packages/server` API를 불러와 디스코드 슬래시 커맨드로 공대표를 보여주는 봇. 빌드 단계 없이 `tsx`로 소스를
바로 실행한다(서버처럼 `nest build` 안 거침 — 봇이 작아서 단순하게).

## 실행

```bash
pnpm --filter @packages/discord-bot run register   # 슬래시 커맨드를 디스코드에 등록 (커맨드 목록 바뀔 때마다 1회)
pnpm --filter @packages/discord-bot run dev         # 로컬 개발 (파일 변경 시 자동 재시작)
pnpm --filter @packages/discord-bot run start       # 프로덕션(pm2가 ecosystem.config.cjs로 이 스크립트를 기동)
```

## 환경변수 (루트 `.env`, 심볼릭 링크로 이 패키지에도 연결됨)

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `DISCORD_BOT_TOKEN` | O | 게이트웨이 로그인용 봇 토큰 |
| `DISCORD_CLIENT_ID` | O | 슬래시 커맨드 등록(`register`)에 사용하는 애플리케이션 ID |
| `DISCORD_PUBLIC_KEY` | - | 지금은 게이트웨이 봇이라 안 씀. 나중에 HTTP 인터랙션 엔드포인트로 바꾸면 필요 |
| `DISCORD_GUILD_ID` | - | 있으면 그 서버에만 즉시 반영되는 guild 커맨드로 등록(개발용, Discord 권장). 없으면 전역 등록(최대 1시간 지연 가능) |
| `BACKEND_URL` | - | `packages/server` 주소, 기본 `http://localhost:4000` |
| `DISCORD_BOT_ADVENTURE_NAME` | - | 아래 "백엔드 인증" 참고, 기본 `디스코드봇` |
| `DISCORD_BOT_SERVER_ID` | - | 서비스 계정 가입 시 필요한 더미 서버값, 기본 `anton` (의미 없음, 봇은 캐릭터를 안 씀) |

## 백엔드 인증 (서비스 계정 방식)

`packages/server`의 조회 API(`/raid-groups` 등)는 전부 세션 쿠키(로그인 유저)가 있어야 한다. 봇은 "로그인"
개념이 없으므로, 전용 모험단 계정 하나(`DISCORD_BOT_ADVENTURE_NAME`, 기본 "디스코드봇")로 `POST /auth/login`
해서 세션 쿠키를 받아 재사용한다(`src/apiClient.ts`). 그 계정이 아직 없으면(404) 그 자리에서
`POST /auth/signup`으로 만든다 — **최초 1회는 자동으로 알아서 생성됨, 수동 셋업 불필요**.

백엔드 코드는 전혀 안 건드렸다 — 기존 로그인/세션 구조를 그대로 재사용하는 쪽을 택함(사용자 확인 사항,
대안으로 별도 API 키 가드나 인증 없는 공개 엔드포인트도 검토했으나 기각). 이 서비스 계정은 캐릭터를
등록하거나 공대표에 배치되는 일이 없으니 `isAdmin=false`인 평범한(사실상 유령) 모험단으로 남는다.

## 커맨드

### `/ping`

살아있는지 확인용. `pong` 응답.

### `/공대표보기`

상위탭(그룹) → 난이도(카테고리) → 기수 순으로 버튼을 눌러가며 탐색. 화면 4단계, 전부 같은 메시지를
`interaction.update()`로 갈아끼우는 방식(새 메시지 안 쌓임).

1. **상위탭 선택**: 생성된 `RaidGroup` 목록을 버튼으로 표시
2. **난이도 선택**: 고른 그룹의 `RaidCategory` 목록(일반/하드/쌀 등), 하단에 "◀ 뒤로 가기"(상위탭으로)
3. **카테고리 요약**: 총 기수 수, 참여 중인 모험단 이름과 인원수(그 카테고리의 모든 기수를 합산 — 그룹 내
   유일 배치 규칙 덕분에 같은 캐릭터가 같은 그룹 안에서 중복 카운트될 일은 없음), 기수별 버튼, 하단에
   "◀ 뒤로 가기"(난이도 목록으로)
4. **기수 상세**: 파티마다 필드 하나씩, 필드 이름은 `파티라벨 [모험단A, 모험단B]` 형태로 그 파티에
   섞여 있는 모험단 이름을 전부 나열(D5 — 캐릭터 줄에는 이제 모험단 이름 안 나옴, 직업만 표시).
   슬롯 한 줄엔 이름/직업 + 역할 아이콘(`<:ico_equi:...>` 딜러 장비점수 / `<:ico_buff:...>` 버퍼
   버프력) + 볼드 숫자, 빈 자리는 취소선(`~~빈 자리~~`). 파티 끝에 평균 장비점수(딜러만 집계, 대시보드
   `RaidBoard.tsx`와 동일 규칙). 하단 버튼 한 행에 "◀ N기수" / "목록으로"(카테고리 요약으로) /
   "N기수 ▶", 그 아래 기수 번호 바로가기 `[1][2][3]...`(최대 15개, 지금 보는 기수는 초록+비활성화)

응답은 채널 전체 공개(ephemeral 아님, 사용자 확인 사항) — 명령 친 사람뿐 아니라 채널의 누구나 버튼을
눌러 같이 탐색할 수 있다.

**색상은 못 넣음(사용자 확인 사항)**: 장비점수/버프력 숫자에 실제 색(파란색 등)을 넣으려면 Discord 임베드
특성상 ```ansi 코드블럭이 유일한 방법인데, 코드블럭 안에서는 커스텀 이모지(`<:ico_equi:...>` 등)와
볼드 마크다운이 전부 깨져서 그냥 글자로 나온다 — 아이콘·볼드 유지와 실제 색상은 동시에 불가능해서
**아이콘 유지, 색상 포기**로 결정함. `---` 같은 마크다운 구분선도 디스코드는 지원 안 해서(공식 확인),
파티 사이 구분은 `embed.addFields()`가 자동으로 넣어주는 필드 간격에 맡김.

**세션/상태 관리**: 서버 메모리에 "지금 이 사람이 어디까지 봤는지" 같은 상태를 안 든다. 대신 각 버튼의
`customId`에 필요한 id(그룹/카테고리/기수)를 전부 실어 보낸다(`rv:<액션>:<id...>` 형식). 액션 코드:
`g`(그룹 목록) · `c`(카테고리 목록) · `s`(카테고리 요약) · `n`/`p`/`x`(기수 상세 — 번호 바로가기/이전/
다음, 셋 다 같은 화면을 그리지만 같은 기수를 가리킬 때 customId가 겹치면 안 돼서 액션 코드만 분리해둠,
`COMPONENT_CUSTOM_ID_DUPLICATED` 에러 원인이었음). 버튼 클릭은 매번 완전히 새로운 디스코드 인터랙션이라
그때그때 새 15분짜리 응답 토큰을 받으므로, 원래 명령을 친 지 30분이 지났든 며칠이 지났든 메시지가
지워지지만 않았으면 그대로 동작한다 — "세션 최소 30분 유지" 요건을 상태 저장 없이 자연스럽게 만족.
버튼 5개당 한 행, 최대 5행(25개)까지만 담을 수 있어서 그룹/카테고리/기수가 25개(기수 번호 바로가기는
15개)를 넘으면 그 이상은 표시되지 않는다 [가정: 지금 규모에서 페이지네이션까지는 과함, 필요해지면 추가].

**슬래시 커맨드가 자동완성에 안 뜰 때 체크리스트**:
1. 봇 초대 링크에 `applications.commands` 스코프가 빠졌는지 확인 — `bot` 스코프만으론 슬래시 커맨드
   자체가 안 보임. 초대 링크 예시: `https://discord.com/oauth2/authorize?client_id=<CLIENT_ID>&scope=bot+applications.commands&permissions=0`
2. `register` 스크립트를 실제로 실행했는지 — 봇 프로세스 껐다 켜는 거랑 커맨드 등록은 완전히 별개 동작.
   봇 재시작은 게이트웨이 연결만 다시 맺을 뿐, 커맨드 목록은 안 바뀜.
3. `DISCORD_GUILD_ID` 없이 전역 등록했으면 반영까지 **최대 1시간** 걸릴 수 있음(Discord 공식 문서 —
   global command는 "read-repair" 방식이라 즉시 반영이 아님). 급하면 테스트 서버 ID를
   `DISCORD_GUILD_ID`에 넣고 다시 `register` — 그 서버에는 즉시 반영됨.

## 커맨드 추가하는 법

`src/commands/`에 파일 하나(`data`는 `SlashCommandBuilder`, `execute`는 핸들러) 추가하고
`src/commands/index.ts` 배열에 끼워 넣으면 됨. 버튼/셀렉트메뉴 등 컴포넌트 인터랙션까지 쓰는 커맨드는
`/공대표보기`(`raidView.ts`)처럼 `handleButton` 같은 별도 export를 두고 `src/index.ts`의
`InteractionCreate` 핸들러에서 customId 접두어로 라우팅해주면 된다.
